# Project agent memory

This file is the project's committed home for project-intrinsic agent knowledge: build, test, release, architecture, and sharp-edge notes that should travel with the code.

- `docs/filesystem-protocol.md` is the authoritative state design; `docs/notification-monitor.md` specifies the private per-data-home JSON-RPC transport, and `docs/read-the-code-review.md` specifies the only other intentional long-lived process: an exact-revision blocking external-event bridge. Neither carries truth, lifecycle authority, recovery, or commander ownership. There is no database or managed runtime.
- `internal/store` owns strict completion/report schemas, immutable correction and review intent, atomic publication, the `state/.lock` mkdir lock, and read-time state/history derivation. Attempts are grouped under explicit product revisions; malformed/conflicting evidence derives `invalid-evidence`, typed non-completion derives `attention`, and `status --all` retains the complete revision/attempt/review chain. Wake lines under `state/` are notifications only and must never be read for truth.
- `internal/flow` is the command core behind every `sophon` subcommand; `cmd/sophon/main.go` is a thin flag layer over it. `flow.Spawn` retries only within a revision; revision owners create immutable correction intent before advancing. Stale-attempt results are refused in `flow.VerifyComplete`. `flow.Status` keeps exact open PRs operational and drains exact verify, validate, and Read the Code review actions; a missing volatile review bridge yields only `review-reconcile`.
- Runtime prompts are embedded by `prompts/embed.go` (`commander`, `workers`, `skills` sets); `SOPHON_PROMPT_DIR` selects a checkout's `prompts/` tree for live development edits. `prompts.Compose` renders the commander prompt; `internal/flow/brief.go` renders worker briefs from the workers set plus the generated task section.
- Workers write only generated attempt-scoped `completion-submission.json` or `report-submission.json`; `internal/flow/complete.go` validates schema/identity and live HEAD under the shared lock before atomically publishing canonical `result.json` or `report.json`. Identical publication is idempotent; differing or report-vs-completion evidence refuses. After durable current-attempt publication the CLI sends a versioned monitor change request, suppressing the direct fixed-message commander wake only when accepted; failures are stderr diagnostics and completion/report retain the direct fallback.
- Spawn resolves the data home once (`datahome.AbsDir`) and propagates it as a `SOPHON_DATA_HOME` launch-environment assignment on every runtime command (`internal/herdr` `initialCommand`/`resumeCommand`) plus pinned assignments in both generated publication commands. Workers must never rely on inherited environment to find the store.
- Delivery requires a fresh `--confirmed` for every push and publishes revision/attempt intent before its external write (`internal/flow/deliver.go`). First delivery creates the public branch/PR; correction delivery rechecks canonical PR identity and uses only an ordinary fast-forward of the same branch, with pending-intent recovery after a landed push. `internal/publicsurface` solely renders/preflights outbound content; correction preserves human-owned PR title/body, and private execution branches are never pushed.
- Local browser review uses only the separately configured versioned `read-the-code-axi` CLI (`internal/readcode`); `docs/read-the-code-review.md` owns the contract. `internal/store/review.go` owns immutable posture history, exact attempt bindings, contiguous event records, classification/routing, and approval derivation. A crash-released exact-owner bridge only performs blocking poll → canonical publication → existing monitor notification; capabilities never enter canonical state, prompts, status, or logs. Required review is rechecked against the product cursor immediately before delivery and never replaces `--confirmed`.
- `sophon commander attach` records the live commander's exact Herdr session/workspace/tab/pane in `state/commander.json` — volatile liveness/presentation routing only, never truth (`flow.AttachCommander`, `internal/flow/commander.go`). Spawn groups workers as tabs into a same-session registered workspace (`herdr.StartRequest.ParentWorkspace`, isolated-workspace fallback on `workspace_not_found`); terminal worker evidence retires the exact worker tab (`flow.RetireWorker`, called by the verify-complete/validate CLI after success, idempotent, no cleanup receipt by design).
- Herdr commands stay behind `internal/herdr.Adapter`; pane ID is the runtime placement. Real-Herdr tests are gated behind `SOPHON_HERDR_LAB=1` with `HERDR_LAB_HELPER`; the ONLY herdr isolation path in tests is the lab helper plus a trailing `--session` argument. Herdr injects `HERDR_SESSION`/`HERDR_WORKSPACE_ID`/`HERDR_TAB_ID`/`HERDR_PANE_ID` into panes; `commander attach` reads them as ambient defaults.
- `sophon send` uses `herdr.Adapter.Submit`: idle prompts wait for affirmative turn start, already-running prompts accept one non-waiting queue acknowledgement, and ambiguous errors are never blindly retried. Husk restoration remains create-before-close; missing exact placement refuses.
- The installed Treehouse lease JSON supplies path and lease identity but not Git metadata; `internal/treehouse` derives branch/base SHA through `internal/git`, and all lease returns must retain both conditional identity guards (lease id + holder).
- Run `go test ./...` and `go build ./...` before delivery.
